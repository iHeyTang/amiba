# 扩展接入评估（持续更新）

结论：多数差异属于需要补适配。缺少实现不等于无法支持；目前没有证据证明某整类普通扩展永久不可能接入。

“不能原样接入”主要指：插件接管整套根页面/输入器，与保留 Amiba 现有能力和样式的要求冲突；或要求当前版本不存在的服务、浏览器没有的原生能力。拆分其附加功能后仍可能接入。

最新验证：同一渲染器内的后台自动出队及前后台交接已通过真实 Host 回归；Stop 保留、立即发送后的连续出队、失败时队列和图片保留均已验证。后台会话重定向的两条连续派发及目标目录恢复也已实测；新旧目标双队列顺序、前台目标交接、跨窗口、跨重启协调及完整 Host inbox 对齐仍待完成。

先看这张简表，后面的 64 行用于逐项查证：

| 情况 | 能否接入 | 确切原因 / 处理方式 |
| --- | --- | --- |
| 附加按钮、设置项、插件视图、命令与工具业务区域 | 可以适配 | 可以接到现有区域和真实服务；已接入口不等于所有第三方组件依赖都已验证。 |
| 官方完整输入服务、新版审批/图片/右侧栏等 | 有适配方向，尚未全部完成 | 需要补齐数据、状态及生命周期；当前缺少实现不是无法支持的证据。 |
| 整套根页面、侧栏、输入器的接管 | 只能部分适配 | 原样替换会改变现有能力或样式；可拆出附加能力，或提供用户主动选择的可选视图。 |
| 一次性子会话继续发送/停止、可续聊子会话图片输入 | 当前官方版本不支持 | 实际 rc.2 公共客户端明确拒绝这些操作；需要上游契约改变，不能靠界面入口绕过。 |
| 冷重启后的嵌套子会话续聊 | 有条件支持 | 直接父 Agent 必须驻留。普通根父可自动恢复；冷父本身是子会话时没有公开的无消息恢复操作。 |
| 依赖官方私有 DOM，或在纯 Web 调用 Electron 系统能力 | 无法通用原样支持 | 前者需要插件改用公共接口或专用适配；后者需要桌面宿主或功能降级。 |

## 普通文件 receipt 的实际依赖核对

2026-09-14 对当前受管 Node 加载的 rc.2 包与固定 c291e796（包版本 0.1.5-rc.2）核对后，普通文件不是仅修改输入参数即可接入。

| 层次 | 当前实际状态 | 完整接入必须完成的工作 |
| --- | --- | --- |
| 附件存储 | rc.2 原包类型仍只有图片；现已由 Amiba Host 插件为旧服务实例补齐 saveFile、saveFileStream、readFileStream、fileHostPath、admitEncodedFile 和错误分类，真实 Host 验证通过 | 存储层已接入，使用独立 official-files/v1；仍需连接 receipt 授权、命令解析与浏览器输入，不代表完整文件上传已完成 |
| 命令接收 | 当前 dsh-commands 0.1.1-rc.2 实际类没有 registerFileReceiptResolver；公开 execute 只接收编码图片，Invocation.attachments 为 ImageBlock[] | 迁移文件 receipt 解析、完整命令输入校验与文件块；不能只把图片回调参数改名 |
| 上传与授权 | 受管 app 无法解析 dsh-client-file-upload（MODULE_NOT_FOUND）；新版 FileUploads 注入 commands、attachments、agents、connection | 注册上传服务及承载通道，按真实 Agent/Session 生成和解析 receipt；不能用原生 att_* ID 替代 |
