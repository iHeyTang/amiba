# 扩展接入评估（持续更新）

结论：多数差异属于需要补适配。缺少实现不等于无法支持；目前没有证据证明某整类普通扩展永久不可能接入。

“不能原样接入”主要指：插件接管整套根页面/输入器，与保留 Amiba 现有能力和样式的要求冲突；或要求当前版本不存在的服务、浏览器没有的原生能力。拆分其附加功能后仍可能接入。

本表逐项覆盖初次审计列出的 64 个官方插槽名称。基线为实际安装的 0.1.1-rc.2 包；新版名称来自初次审计固定提交 c291e796，仍需逐个迁移验证，不代表已支持所有新版插件。初次报告将本地源码当作 npm rc.2 的地方已发现不一致，尤其 settings.plugin.item，不能继续沿用旧结论。

## 不只涉及 UI 槽位的边界

| 项目 | 判断 | 确切限制 |
| --- | --- | --- |
| 官方 sessions.open | 已适配并实测 | 插件可从首页主动打开会话；启动恢复不会因此替换首页。clear 和子会话渲染另核对。 |
| 同版本 Host 插件、工具、生命周期 | 原生机制可用 | 每个插件声明的服务和外部依赖仍必须满足。 |
| 官方组件样式 | 可适配，待完成 | 需提供局部样式资源，不能全局覆盖 Amiba 主题。 |
| 官方完整 useInput/inputActions | 尚不能宣称全部支持 | 尚缺草稿附件及提交状态的完整桥接；没有证据可断言永久无法适配。 |
| 会话 ZIP 导出 | Desktop 已实测，Web 待实测 | Desktop file: 不能靠普通相对链接下载，已增加限定到运行时导出端点的原生交接。 |
| 直接操作官方私有 DOM 的插件 | 无通用兼容保证 | Amiba DOM 不同；需要插件改用公共接口或提供专用适配。 |
| Electron 专属能力在纯 Web 使用 | 无法原样支持 | 纯浏览器没有 Electron 主进程和相应系统 API；需桌面宿主或功能降级。 |
| 要求新版服务的插件 | 不能直接承诺支持 | 必须迁移服务/模块图或提供语义等价桥接；增加类型声明无效。 |

实现及验证记录见 [兼容实施清单](dsh-extension-compatibility-plan.md)。以上是逐项评估，不是全部兼容完成声明。
