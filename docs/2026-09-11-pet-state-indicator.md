# 宠物状态指示器评审

原气泡只展示通知，进行中会话没有进入通知通道；原 PetView 强制身体 state=0，只切换少量表情。现在服务端为每个执行中会话维护独立临时记录，复用长轮询同步，但不保存到通知历史、不触发系统通知，也不因已读而隐藏。

等待处理优先，其次进行中，再次未读结果。同一会话等待时隐藏重复执行卡片。turn/end 删除临时记录，结果继续使用既有已读/忽略语义。断线时隐藏失效的执行记录，展示重连提示和加载动作。

| 状态来源 | 宠物阶段 | 行为 |
|---|---|---|
| 无执行、历史完成快照 | idle | 日常轻动作 |
| 窗口初始化、首次订阅、连接失败重试 | loading | 明确加载文字、持续进度提示；服务连接阶段轮换加载动作 |
| 输入 active / composing | typing | 输入与输入法组合；不读取输入内容 |
| turn/start、reasoning-delta | thinking | 每个会话独立跟踪，重复 chunk 不产生状态更新 |
| text-delta | responding | 回复动作 |
| tool/call、tool/result | tooling | callId 集合跟踪并行工具，最后一个工具结束后恢复基础阶段 |
| approval/asked、ask_user_question 生命周期 | waiting | 使用真实审批/提问通知，完成后恢复执行 |
| turn/end completed | completed | 播放一次四动作序列后回到日常动作 |
| turn/end error | failed | 播放一次错误与恢复序列 |
| turn/end 其他原因 | interrupted | 播放一次停止与稳定序列 |

前台宠物使用 SurfaceActivity 与 SurfaceInteraction。桌面宠物使用服务端事件，覆盖后台会话、子会话和由相同会话机制执行的定时任务。尚未触发的日程不显示成执行中。重试、上下文压缩、工具内部步骤没有独立稳定的 SurfaceActivity 阶段，仍使用实际 thinking/tooling 状态，不从工具名猜测结果。

两个 2D 骨架各为原有 14 + 新增 52 = **66 个动作**；3D 为原有 8 + 新增 52 = **60 个动作**。每个场景有四个新动作。新增动作使用骨架参数与确定性曲线，保留轮廓、耳朵、饰品和已有点击反应。原编号保留；新增编号为 2D 的 14–65、3D 的 8–59。原 Bloub 自动参考序列仍为前 14 项。

完整动作清单见 Mofli 的 `docs/companion-actions.md`。工作阶段只轮换对应动作；玩耍、亲近和休息动作可在 Studio 选择、保存、导出。Amiba 预览提供十个阶段按钮。静态模式固定姿态。

3D 使用独立 WebGL 渲染。桌面命中与可见边界读取渲染 alpha，透明部分穿透点击；缩略图转为静态图片后释放 WebGL 上下文。首次主窗口加载保留原宠物资源，增加进度动效和加载文字。

Amiba 默认安装线上发布的 Mofli 版本。上文新增动作与 3D 能力需要相应资源版本；当前锁定的线上 `0.1.1` 使用 2D 骨架与表情反馈，不包含这些未发布能力。

本地宠物插件通过 DSH profile 的依赖链接、Loader 配置和 HMR 联调，Mofli 库只作为该插件项目的依赖。托管运行时通过 npm 锁文件安装，不复制本地资源包，也没有按宠物品牌定制的联调开关。具体步骤见 [通用插件开发流程](local-plugin-development.md)。
