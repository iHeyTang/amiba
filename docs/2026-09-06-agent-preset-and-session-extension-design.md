## 已确定的范围

- 保持官方 standard、code、minimal、cordis 的定义不变。
- 移除 connector-core 自动生成 restricted 的产品行为；IM 来源不产生额外能力限制。
- 大管家作为插件对基础预设的会话级扩展，不再生成 amiba-steward 预设。
- DSH 继续是预设、Agent、Session、工具、提示词和审批的运行时真源；不建立 Amiba 的第二套预设引擎。

## 1. 什么是预设

预设是可命名、可复用、独立于某个会话存在的 Agent 基础组装。用户选择它，是选择一套默认的工具集合、提示词、工具呈现方式与运行行为。它不只是一段角色提示词。

DSH 将预设挂载为共享的常驻 scope，会话的解析链为 agent → preset → global。运行中的会话维持它加入的组装代际，预设编辑影响后续创建的会话。默认值是未显式选择时使用哪个预设的设置，不是预设分类；新会话必须记录实际解析到的 ID，恢复不能重新取当时的默认值。

可以构成独立预设：可跨会话复用的个人工作方式、用户明确创建的自定义组合、官方四种运行模式。

不构成独立预设：一次消息来自 IM、一个会话由插件管理、某次任务需要回报给大管家、插件为了方便初始化临时写出的配置。

## 2. 预设决定什么，哪些事情不能靠它保证

| 层次 | 所有者与责任 |
| --- | --- |
| 基础能力与行为 | 预设选择工具插件、提示词、技能加载、压缩/计划等机制、原生或 Code Mode 工具呈现 |
| 场景能力与行为 | 插件在特定 Agent 的作用域追加工具、角色指令、结果回报与交互方式；必要覆盖必须显式定义 |
| 操作授权 | 宿主工具执行守卫、审批、沙箱、凭据与资源授权决定操作能否发生；扩展不能解除这些约束 |
| 连接入口 | 连接负责身份、路由、工作区、基础预设及交互适配；IM 不自动改变能力 |
| 生命周期与展示 | 会话归属和用途决定由谁恢复、在哪里显示，不从预设名称推断 |

预设没有提供某个工具，会影响基础 Agent 能否调用它，但这不是不可扩展的能力上限。受信任插件可以在当前 Agent 追加工具。trust 是目录信任/创作标记，不是授权等级，不表示创建者，也不能用来判断可见性。

大管家派发到任务会话的操作仍须经过目标任务自己的执行约束，不能通过派单绕过目标授权。一次消息的 source.plugin 只标记消息来源，不足以证明整个会话由插件拥有。

## 3. 会话扩展契约

复用 DSH 原生 scope 和 setup，实现顺序是：解析并固定基础预设 → 挂载基础预设 → 安装插件会话扩展 → 校验最终组装 → 发布 Agent。任一步失败整体回滚，不捕获异常后带着半套能力继续运行。

扩展是插件代码提供的安装逻辑，不是另一个文件夹预设、动态预设 ID 或静默复制的 YAML。首次可先在 steward 插件中实现明确的 setup 函数，不为一个场景提前建立通用扩展市场或第二套运行时注册表。

安装逻辑必须说明：所属插件与行为版本、追加的工具/提示段、覆盖项、依赖服务、兼容条件、恢复方式、派生会话继承规则与释放逻辑。同层工具重名不能静默覆盖；角色 persona 等明确的覆盖点只允许一个所有者，冲突在 setup 阶段报错。

扩展默认追加能力，不隐式裁剪基础预设。若某个产品角色确实要求只允许调度工具，必须单独声明这是该角色的执行策略，并用 DSH restrict/guard 实施，不能借“内部预设”或“IM”之名引入。当前大管家“永不亲自执行”的旧行为不应在改造时被不加讨论地保留成隐藏权限限制。

### 基础预设兼容性

- standard：在会话层添加调度工具与角色指令，继承基础运行机制。
- code：继承 Code Mode。新增工具应进入同一个工具目录及 SDK；不能用完整提示词替换把 tools:sdk/code-only 协议抹掉。
- minimal：原 persona 设置 complete: true，随便追加提示词不会生效。需要显式的会话 persona 覆盖以容纳大管家角色，这是扩展契约的一部分，不能宣称“无条件追加即可”。它没有上下文压缩；如大管家要求长期连续会话，应由扩展补足经校验的压缩服务，或声明不兼容，不能静默切回 standard。
- cordis：保留基础创造能力，明确大管家角色优先的任务调度指令，校验最终提示词不存在互相矛盾的行为。

“任何预设可叠加”应成为经过测试的兼容目标，不是未经验证的机制承诺。自定义预设可能缺服务或有完整提示词与工具协议覆盖，需要给出具体不兼容原因。不会因仅选了 minimal 就强迫所有扩展永远保持两个工具；详情须如实显示扩展后的有效能力。

## 4. 大管家的目标结构

大管家拥有一个基础预设上的调度会话，以及一组各自保留基础预设的任务会话。

- 调度会话：记录基础预设 ID；会话层安装角色提示词、steward_* 工具与回报处理；由 steward 插件拥有和恢复。
- 被管理任务：仍是普通任务。只安装明确需要的回报/询问用户适配，不继承调度工具和内部展示用途。当前 guardAskUser 的实时接管路径也必须纳入统一挂载/释放，不能只有创建与恢复路径安装它。
- 被接管的既有任务：保留预设和历史；在轮次安全边界附加管理关系并记录，不在工具调用进行中突然替换组装。
- UI：大管家专有入口展示“基础预设 + 大管家功能”；普通预设名单不出现大管家。隐藏的是插件拥有的调度会话，不隐藏使用相同 standard 的普通任务。

移除 preset-seed、agentPresetsRoot 配置和 hidePreset 依赖。不要把旧大管家整份 complete 提示词直接搬过去，否则会继续破坏 Code Mode 的提示协议。

## 5. 恢复与无残留

不生成预设文件并不等于不能持久化。应区分需要恢复的业务数据和可丢弃的运行资源。

| 数据 | 生命周期 |
| --- | --- |
| 工具注册、提示词、监听器、守卫、计时器与临时服务 | Agent/插件 scope 拥有；关闭、失败、卸载时释放；不写入预设目录 |
| 会话所用基础预设、插件归属/用途、扩展行为版本与必要参数 | 写入 DSH 支持的会话元数据/事件，通过同一会话日志投影恢复，不新建第二份会话事实表 |
| 大管家任务映射和已汇报游标 | 插件业务状态；已有 state.json 可承担该职责，不替代 DSH 会话历史 |
| 用户消息和已完成任务历史 | 用户数据；停用插件不自动删除 |

元数据/事件字段需在实现时按 DSH 可扩展契约落地，不能假定 owner/extensions 是现成官方字段。记录的是插件拥有关系与扩展版本，不持久化闭包或另存完整预设副本。

所有可恢复入口必须遵循同一个组装描述，包括插件重启、普通 UI 打开、冷读历史和派生会话。插件拥有的调度会话由其所有者恢复，通用 UI 不可先创建缺扩展的 Agent 再补工具。插件缺失时可以读历史，继续运行应明确显示需要该插件；不能悄悄退化成普通聊天。

运行中会话的组装保持稳定。停用或升级必需扩展时先停止并排空相关运行，再释放；后续恢复按记录版本校验。持久化行为版本可检测不兼容，不等于自动归档并重放旧插件二进制。

Fork、子代理、转交不默认复制所有扩展。基础预设按官方语义继承，插件管理关系只通过明确的接管流程建立；调度角色不能传染给普通任务。已拥有的调度会话不允许通用恢复入口抢占其运行所有权。

## 6. 未发版的数据边界

当前没有已发布的历史格式兼容承诺。移除 restricted 与 amiba-steward seed、启动迁移、旧引用修复和大管家旧会话换新分支；不自动扫描、改写或删除开发环境的历史文件。同名开发数据不会被硬编码隐藏，也不会被当成官方预设。

后续正式发布的数据升级遵循 [core 与插件统一数据升级约定](./data-upgrades.md)。该约定目前是设计，不存在可执行迁移链。会话扩展的行为版本检查仍保留，它用于阻止不兼容组装，不代表已实现数据转换。

## 7. 展示规则

官方四个预设的定义、能力和顺序保持原样；各入口用同一 DSH roster 与映射规则，管理页去掉“只显示 user”的过滤，保留默认标记。不可编辑的内置项显示只读详情和复制操作，而不是从管理页消失。

普通预设页只管理真正的预设；连接选择器使用同一份名单，IM 不额外筛掉编码能力。损坏预设在管理页保留错误原因，在选择器不可新选。业务扩展出现在所属插件/会话详情，不额外增加预设行。可查看有效工具和扩展来源，避免基础预设名称掩盖实际运行差异。

## 8. 实施次序与验收

先验证四种基础模式的会话扩展与恢复能力，再替换大管家组装，随后移除 seed、统一名单。当前不承担未发布数据的自动转换。

必要验证：

- 开关插件、反复创建/销毁大管家不会改变预设目录与名单，官方四个预设文件不变。
- 大管家工具只出现在目标会话；同预设的普通会话与任务不会被污染或误隐藏。
- Code Mode 可实际派单；minimal 的角色提示词确实生效，并验证长会话策略；standard/cordis 的有效组装符合声明。
- 新建、重启恢复、UI 冷打开、fork/子代理、接管既有任务具有明确一致的扩展行为。
- 注册冲突、缺依赖、插件缺失、安装到一半失败均无半成品 Agent 和遗留监听器。
- IM 与桌面在相同基础预设、相同资源授权下能力一致，不出现 IM 专属受限逻辑。
- 验证运行期卸载能停止相关 Agent 并释放作用域资源；业务历史保留且可读。

本提案不承诺当前 DSH 能自动完成任意扩展恢复：底层已提供作用域组装和释放机制，产品仍需补齐所有权记录、恢复入口一致性、兼容性校验。

## 实施记录

- 新增核心宿主插件 session-features：只注册 DSH 会话扩展的安装回调。需要它的原因是普通 UI 也可以恢复插件会话；只在 steward 的私有 setup 中安装无法覆盖该入口。通用恢复使用 DSH 同步 agent/created 事务安装，提示组装与工具执行检查必需扩展；插件卸载取消并等待相关 Agent 空闲。
- DSH SessionHeader 不支持任意 owner/extensions 字段，因此使用带精确 sessionId 的 ignorable 插件事件；Amiba 执行入口强制校验，fork 不继承拥有关系。
- 大管家保留基础工具和运行机制；覆盖 persona 槽而非完整系统提示词。minimal 不额外安装压缩，其长期上下文限制保持官方基础模式的行为。

验证：403 项相关测试通过；涉及包构建及类型检查通过。全仓 verify:pluginization 通过；verify:architecture 因当前浏览器插件缺少 browser.image.error 翻译键而未通过，该项不属于本次预设改动。该验证记录属于初次预设改造；后续已按未发版前提移除具体迁移，验证结果见本次交付说明。
