# 直接使用 DSH 官方 Provider 接口，由 Amiba 实现 UI

## 最终架构

Provider 插件直接遵循 DSH 官方的扩展契约，使用官方的注册、配置和凭据接口。Amiba 负责自己的界面实现，浏览器端直接调用：

- `llm.providers`：获取官方 Provider 目录及其配置入口。
- `llm.models`：获取官方模型目录。
- `settings.*`：读取插件声明的配置结构，并保存配置。
- `credentials.*`：查询密钥配置状态、保存和删除密钥。
- `sessions.models/selectModel`：查询和切换当前会话的模型。
- `agent-default-model` 配置命名空间：保存新会话使用的默认模型。

此前增加的 `amibaModelPlane` 中间 RPC、自有 Provider 服务，以及旧的 Provider 驱动、模型发现和运行时投影代码均已移除。本次功能没有修改或分叉 DSH 官方实现。

React 的界面状态和表单辅助代码只在 UI 内部使用，插件无需实现这些内部接口。旧注册表的读取和转换代码仅用于一次性迁移历史数据。

## 官方 ABC，加上可选增强 D

标准社区插件只要提供官方定义的 ABC 能力，就可以正常使用，无需声明 Amiba 专有字段。

Amiba 自己增加的 D 能力遵循以下边界：

- D 是可选增强，不能成为使用 ABC 的前提。
- 如果 D 需要插件配合，应通过独立的可选声明判断插件是否支持。
- 插件没有声明 D 时，只停用对应的增强功能，官方 ABC 仍然正常工作。
- 本次没有为尚未确定的 D 能力提前设计一套新的插件注册协议。

已有的「模型显示／隐藏」属于纯 UI 增强。它的偏好保存在 UI 自己拥有的 `amiba-model-ui` 配置命名空间中，通过官方 settings 接口读写。隐藏模型只影响 Amiba 的模型菜单，官方模型目录、Provider 的运行能力和其他客户端均不受影响。

内置的配置表单直接读取插件的官方声明和配置 schema。插件即使没有声明可编辑的配置表单，其模型仍然可以出现在选择器中。需要交互式登录等特殊授权流程的插件，可以增加相应的 UI 扩展，不必改变官方模型调用流程。

## TokenDance 的实现

TokenDance 使用一个独立插件，注册一个 `tokendance` Provider。

DSH 公开导出的 `PiAiAdapter` 可以接收带有 API 映射的 pi-ai Provider，因此能够按模型选择协议。无需拆成三个插件，也无需创建三个虚拟 Provider ID。

目前支持：

- OpenAI Chat Completions。
- OpenAI Responses。
- Anthropic Messages。

三种协议均复用官方适配器的消息转换和工具调用处理。直连 DeepSeek 继续使用已有的官方插件。

TokenDance 的公开模型目录提供各模型支持的协议；插件随包附带的目录快照包含 64 个聊天模型。该插件可用于 DSH `0.1.1-rc.2`，不需要额外进行 Amiba 专用注册。

尚未支持的非聊天协议和 Google 原生协议不纳入模型列表。目录没有提供的模型能力信息，不根据模型名称猜测。

## 验证结果与范围

已通过的检查包括：

- 33 项模型 UI、历史数据迁移和插件生命周期测试。
- 类型检查和插件边界检查。
- 最终桌面托管运行时构建及 `runtime:verify`。
- 使用官方原生 API 的 Model Plane 专项运行时冒烟检查。其中实际修改了 UI 显示偏好，并确认官方 TokenDance 模型目录保持不变。

UI 测试覆盖了普通社区插件不声明任何 Amiba 专有字段时的使用情况，以及模型显示偏好、官方配置版本冲突、凭据操作、原样保留的推理强度 ID、默认模型、模型发现和插件卸载。历史数据迁移及原有 UI 测试也已保留。

TokenDance 测试通过本地 HTTP/SSE 实际验证三种协议，并验证官方插件的加载、配置更新和卸载流程。

此前的全项目架构检查遇到了已有的 UI shell 依赖注入声明与校验预期不一致的问题；完整运行时冒烟测试遇到了外部后台任务通知的断言失败。这些问题与本次 Provider 改造独立。Provider 专项运行时检查已改为仅使用官方原生 API，并验证可选 UI 设置不会改变官方模型目录。

本次尚未使用真实 TokenDance 账户密钥进行生产环境模型生成调用。

## 模型目录、凭据状态与菜单开关

设置页保留官方返回的完整服务商和模型目录，供用户查看与配置。模型选择器则额外检查官方路由是否已注册、模型目录是否成功加载，以及插件声明的凭据引用是否已配置。

未配置、没有模型、目录加载失败或缺少已声明凭据的服务商，其显示开关保持关闭，不能手动强行开启，也不会进入可选模型或被采用为新会话默认模型。保存或删除密钥后，界面通过官方事件重新计算状态。用户手动关闭的菜单偏好会保留，不会因为补齐密钥而被覆盖。

不声明凭据引用的本地服务或由插件自行处理认证的服务，不会被强制要求填写 Amiba API Key。这里判断的是官方接口可观察到的配置条件，不通过收费模型请求验证密钥、余额或账户权限。官方运行时仍负责实际调用时的认证处理。

图标方面，修正了内联 SVG 地址在 CSS 遮罩中缺少引号的问题，避免遮罩失效后出现实心方块。Kimi、OpenRouter 使用随主题文字颜色变化的单色图形，彩色图标在深色主题下提高亮度，并补齐部分 DSH 官方服务商 ID 的图标映射。构建后的图标已在浏览器中检查浅色和深色背景。

本轮 38 项模型 UI 测试、6 项图标测试及对应类型检查通过。


### TokenDance 路由生命周期修正

TokenDance 与官方 `llm-pi-ai` 一样，使用默认空的 `providers` 配置字典。未保存配置时只声明可配置服务商，不注册运行时路由，也不自动请求模型目录。保存 `llm-tokendance.providers.tokendance` 后注册路由；删除该配置后注销路由。凭据检查与路由注册分开处理，UI 可见性开关仍只是可选的展示偏好。此前根级别的 TokenDance 配置字段现移至该路由配置内。
