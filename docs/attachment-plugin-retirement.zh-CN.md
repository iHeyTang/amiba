# Amiba 附件插件退役

范围：DSH 0.1.5-rc.1 升级分支。用户决定使用官方附件实现，不迁移旧数据，不保留独立 PDF 提取插件。

## 最终职责

| 部分 | 归属 |
| --- | --- |
| 草稿文件、图片预览对象、后台上传、进度、失败重试、发送凭证 | 官方 ConversationController / FileUploadRuntime |
| 持久文件和图片、会话中的附件引用 | 官方 DSH 附件服务 |
| 文本读取 | 官方 read 工具 |
| PDF 内容分析 | Agent 根据环境选择通用工具；不再内置 Amiba PDF 提取工具或保证预装解析依赖 |
| Amiba 输入框和桌面文件/截图入口 | 保留必要连接，交给官方草稿控制器；不创建 Amiba 附件对象存储 |

## 删除范围

- `plugins/dsh-plugin-attachments` 全部代码、专属依赖和分发清单。
- Core bundle 的插件注册及根目录配置。
- `amibaAttachments` 自定义 Remote、`att_…` 存储及会话引用保留逻辑。
- `attachment_read_text`、`attachment_read_pdf`、配套系统提示和工具卡片。
- 新消息中的自定义附件描述块；发送官方图片数据或文件凭证。
- 主进程的旧附件存储门面。截图和外部文件入口只传递文件内容，接收页面创建官方草稿。

## 数据行为

不导入旧附件，不转换旧 ID，不删除用户磁盘上的旧附件文件。旧消息中的文本可以继续打开；旧附件不保证可以继续读取，需重新上传。

新附件草稿遵循官方浏览器运行时生命周期：跨会话切换由官方重新绑定文件凭证；页面重载后已经丢失的未发送草稿对象需重新选择。已发送的新附件使用官方持久会话记录。

## 独立事项

工作台 PDF.js 预览不属于附件插件。本次退役不删除工作台文件预览。将 PDF 预览改为内置浏览器打开，需要独立验证后实施。

## 验证记录

附件相关运行时 51 项、UI 12 项和输入触发/命令流程 33 项测试通过；完整管理运行时 smoke 验证官方上传、跨会话凭证隔离和消息持久化。实际 Electron 中已验证官方草稿创建、上传就绪、生成文件发送凭证、释放草稿及输入框文件选择。以上不代替整个升级 PR 的三平台 CI。
